# Coding Guidelines

## Functional Programming
- Prefer pure functions and stateless components.
- Avoid side effects and shared mutable state.
- Use higher-order functions, map/filter/reduce, and composition.

## DRY Principle
- Do not repeat yourself; extract reusable logic into functions or modules.
- Refactor duplicate code promptly.

## Terse Syntax
- Write concise, readable code.
- Use modern language features (e.g., arrow functions, destructuring, template literals).
- Avoid unnecessary verbosity and boilerplate.

## Example
- Use array methods instead of loops for transformations.
- Prefer `const` and `let` over `var`.
- Compose small functions for complex logic.
